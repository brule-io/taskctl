# One experimental IDL and client projection

The bounded kernel has one vertical projection: a custom Kotlin AST describes its
wire envelopes and three HTTP operations, produces a Smithy 2.0 JSON AST, and
generates a Python client with nominal identity/envelope types. The core codecs
and `LedgerTransitions` remain authoritative for task and lifecycle semantics.
This is a development experiment, not a frozen protocol, published SDK or service.

`idl/src/main/kotlin/io/brule/tasking/idl/WireModel.kt` is the authored projection.
Validated shape and field names retain separate Kotlin types. Generated files in
`idl/generated` include the custom AST, Smithy AST and Python client. Rebuild with
`./gradlew :idl:generate`; `:idl:test` rejects byte drift. Root `check` includes
these checks and the Kotlin type-safety policy covers the IDL module. Smithy and
PostgreSQL dependencies remain outside the CLI/native runtime.

The real Smithy model assembler, pinned to `1.73.0`, validates the projected model.
Smithy's [JSON AST](https://smithy.io/2.0/spec/json-ast.html) supplies shapes and
references; [HTTP bindings](https://smithy.io/2.0/spec/http-bindings.html) describe
the existing routes. A declared
[custom protocol trait](https://smithy.io/2.0/spec/protocol-traits.html) identifies
`kernelJson`. It is not AWS restJson1 or Smithy RPC v2 and cannot be given a stock
protocol serializer merely because the model validates.

## Scope and exact values

The slice models snapshot, apply/result, event/page and error envelopes. The Value
union projects null, boolean, string, arbitrary integer, decimal, array and object
separately. This custom wire maps that union to existing untagged typed JSON and
requires nullable fields to be explicitly present. It does not flatten all values
into a float-based document. Decimal category and scale, large integers, object
order and Unicode survive round trips. Canonical hash verification uses the core's
framed encoding and UTF-16 ordinal map ordering, with exact decimal arithmetic.

Generated structures validate fields, protocol literals and nominal IDs. The
shared runtime immediately converts stdlib JSON output into a closed immutable
value algebra at a named decoding boundary. It rejects duplicate keys, malformed
Unicode and noncanonical wire bytes. Integer conversion does not depend on or
alter Python's global digit limit. Decimal canonicalization does not depend on
ambient Decimal precision. Acceptance-time validation retains nanoseconds and
the original string while checking core-produced valid/invalid time witnesses.

Task/planning records and transition-specific evidence inside a snapshot or
transition are carried as typed Value subtrees. This deliberately bounded client
does not duplicate the task reducer, compute frontier/readiness or claim complete
language-native task authoring APIs. The server validates those domain subtrees.
The Smithy artifact describes wire structure; it does not authenticate an event
or turn an actor assertion into proof of task truth.

The generated methods use an explicit loopback HTTP endpoint. They verify snapshot
and event digests, retain distinct HTTP errors, bound request/response sizes and
perform no redirects, proxy discovery or automatic application retries. Canonical
decimal expansion is also bounded in this experimental client. These are adapter
limits, not new core validity rules. A lost reply remains an uncertain outcome to
inspect. No client operation writes repository state or invokes Git.

## Interoperability evidence

```text
./gradlew :idl:test
python idl/tests/run_tests.py
python scripts/kernel_test.py --idl
```

The last command uses the same digest-pinned, explicitly disposable PostgreSQL
harness as the kernel and removes its exact container afterward. It starts only
scoped loopback test listeners. The client is generated before checking in the
artifact; tests check its bytes and run that exact checked-in output.

Four JVM projection tests validate Smithy, generated byte reproducibility, name
boundaries and core-generated wire/digest/time witnesses. Eight Python tests cover
those witnesses plus precise numbers, immutable containers, malformed input,
nominal IDs and endpoint/cursor rejection. Two real PostgreSQL/HTTP tests exercise
seed, independent roadmap/epic data, closure receipts, stale CAS, invalid/premature
closure, complete event history and cold reconstruction. A second case loses the
reply after a real committed seed and proves exactly one request and one event.

The interoperability harness compares the returned complete snapshot and each
event against the Kotlin kernel, verifies opaque values and historical receipts,
and checks an unrelated repository marker's bytes/mtime. Python bytecode cache
writes are disabled during proof runs. Exact source, generated-artifact/JAR hashes
and test records are collected before canonical task closure. Three-platform
JVM/native product parity remains a separate regression gate; the IDL/client code
is not linked into the native tool.

This result supplies one client before considering a language matrix. It does not
authorize a new server repository, deployment, authentication/tenancy model,
automatic replay, managed executor, consumer migration or native-v1 freeze.
